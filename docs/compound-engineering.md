# Compound Engineering: how it works and what makes it distinctive

> Reference: [Research quest #14](raw/quest-14-compound-engineering.md)

**Scope.** This review uses the upstream repository at commit [`4fbabcd`](https://github.com/EveryInc/compound-engineering-plugin/tree/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64). I inspected it on 2026-09-23. The repository reports 36 skills and support for 14 agent hosts, including Claude Code, Cursor, and Codex. [`README.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/README.md#L15-L19)

### What it is

Compound Engineering is a plugin of user-facing skills for coding agents. Its central claim is that engineering work should leave reusable artifacts and knowledge that reduce the effort required for the next change. The plugin combines planning, execution, review, and knowledge capture in one workflow. [`README.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/README.md#L109-L124)

The primary runtime unit is a `SKILL.md` directory. A skill has a user-facing description, an outcome, a done condition, and phase-specific reference files. The design keeps specialist behavior inside the owning skill. When a skill needs another perspective, it dispatches a generic subagent. The subagent receives a specialist prompt from the owning skill rather than appearing as a standalone plugin agent. [`CONCEPTS.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/CONCEPTS.md#L5-L18) [`AGENTS.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/AGENTS.md#L214-L224)

The repository separates three layers:

1. **Skills and orchestration.** The 36 skills cover the core loop, on-demand work such as debugging and explanation, Git operations, testing, collaboration, and autonomous execution. [`docs/guides/README.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/README.md#L35-L77)
2. **Durable project knowledge.** Skills write plans and solutions into the repository. `ce-compound` stores qualifying learnings under `docs/solutions/`; later planning and ideation read those learnings as grounding. [`docs/guides/ce-compound.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/ce-compound.md#L1-L13) The optional Compound Packs mechanism adds declared, prescriptive rules that planning and review can quote and cite. The plugin treats pack text as evidence rather than executable instructions. [`docs/guides/packs.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/packs.md#L1-L11)
3. **Host integration.** The plugin provides host manifests and native adapters. Its OpenCode adapter discovers each skill’s front matter and registers the skills and commands. Its Pi adapter exposes the shared skill directory. [`compound-engineering.js`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/.opencode/plugins/compound-engineering.js#L29-L103) [`compound-engineering.ts`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/.pi/extensions/compound-engineering.ts#L1-L12) The Bun CLI parses a Claude plugin’s agents, commands, skills, hooks, and MCP servers. It passes the parsed plugin to target-specific converters and writers. [`claude.ts`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/src/parsers/claude.ts#L14-L36) [`index.ts`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/src/targets/index.ts#L37-L76)

### How the workflow works

The normal operational loop is:

1. **Brainstorm.** `ce-brainstorm` answers what to build through one-question-at-a-time dialogue. It writes a unified plan that contains only requirements when the team decides that a durable artifact is warranted. It does not implement code. [`ce-brainstorm/SKILL.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/skills/ce-brainstorm/SKILL.md#L7-L19)
2. **Plan.** `ce-plan` answers how to carry out the agreed work. It researches the repository and external sources, resolves technical choices, and writes a plan. It does not implement or test production code. [`ce-plan/SKILL.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/skills/ce-plan/SKILL.md#L7-L21)
3. **Work.** `ce-work` executes an implementation-ready plan. Its contract makes the host orchestrator retain authoritative verification, integration, and canonical commits. [`ce-work/SKILL.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/skills/ce-work/SKILL.md#L7-L14)
4. **Simplify and review.** The standard loop simplifies new code, then runs `ce-code-review`. Review selects personas from the actual diff and dispatches applicable reviewers in parallel. It then merges and deduplicates findings and records both their severity and how to fix them. The review is report-only unless local application is explicitly authorized. [`README.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/README.md#L126-L139) [`docs/guides/ce-code-review.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/ce-code-review.md#L1-L17)
5. **Compound.** `ce-compound` captures a solved problem only when its reasoning is non-obvious, durable, and costly or risky to lose. It checks for overlap and validates claims against the tree. It then writes a bug-track or knowledge-track document. Later planning and ideation use that learning. [`docs/guides/ce-compound.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/ce-compound.md#L26-L46) [`docs/guides/ce-compound.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/ce-compound.md#L112-L128)

`ce-ideate` is an optional prelude for teams that do not yet know what to work on. The catalog lists it separately from the four core iteration stages. The root README includes simplification and review in its six-step operational loop. [`docs/guides/README.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/README.md#L13-L45)

The autonomous entry point, `lfg`, routes a request to the skill responsible for its result. For code changes, it requires a work source that the current run produces: an implementation-ready plan or a `fixed` result from `ce-debug`. It then implements the change, simplifies the code, runs the review, applies eligible fixes, captures the learning, runs browser tests, commits and pushes the branch, creates a PR, and repairs CI within a fixed limit. It does not merge the PR. [`docs/guides/lfg.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/lfg.md#L1-L21) [`docs/guides/lfg.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/lfg.md#L74-L93)

### What is distinctive

**The feedback process persists in repository artifacts as well as in conversation.** Compound Engineering records the solved problem as an artifact that later runs can retrieve. The mechanism is how solution documents influence future brainstorming and planning. Compound Packs can also make reusable rules available across repositories. [`README.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/README.md#L126-L149) [`docs/guides/packs.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/packs.md#L256-L289)

**The framework is contract-driven and stage-separated.** Brainstorming owns product requirements, planning owns technical design, work owns implementation, and review owns findings. `lfg` reinforces this separation with the rule that code cannot be implemented without a verified work source. This reduces the chance that one agent turns a short prompt into code while inventing unstated requirements. [`ce-brainstorm/SKILL.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/skills/ce-brainstorm/SKILL.md#L7-L17) [`ce-plan/SKILL.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/skills/ce-plan/SKILL.md#L7-L15) [`docs/guides/lfg.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/lfg.md#L97-L117)

**Review is adaptive rather than a fixed panel.** Every multi-agent review includes correctness. Testing, security, performance, migration, reliability, standards, and adversarial checks are selected based on the changed code. The review chooses lite, focused, or full depth according to the change’s likely consequence. A local adversarial pass can use a different model provider. If no eligible peer CLI is available, the plugin uses a local reviewer instead. [`docs/guides/ce-code-review.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/ce-code-review.md#L76-L101) [`docs/guides/ce-code-review.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/ce-code-review.md#L125-L135)

**Knowledge is separated from instruction authority.** A skill is executable workflow guidance. A Compound Pack is repository or organization knowledge that the agent quotes and cites. The plugin treats pack text as untrusted evidence, so a malicious or mistaken rule cannot tell the reviewer to skip a check just because it appears in a pack. [`docs/guides/packs.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/packs.md#L291-L308)

**Portability is part of the architecture.** The project authors the skill corpus once, then exposes it through native manifests, host adapters, and converters. Each converter translates invocation syntax, tools, paths, agents, and output semantics for its target. The source code makes target-specific converter and writer pairs explicit. [`AGENTS.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/AGENTS.md#L99-L107) [`AGENTS.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/AGENTS.md#L198-L203) [`src/targets/index.ts`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/src/targets/index.ts#L37-L76)

### Intended use

Use the plugin when a developer or team wants agents to follow a repeatable engineering process instead of only editing code. Use the staged skills when you want to inspect requirements, plans, implementation, or review findings between stages. Use `lfg` when the work is defined enough to run without those approval points and you accept a branch it pushes and a PR it opens. The maintainers describe the plugin as opinionated and say that some proposals will not fit its approach. [`docs/guides/lfg.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/lfg.md#L121-L137) [`README.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/README.md#L448-L454)

### Tradeoffs and limitations

- **More structure costs more context and execution.** Full `ce-compound` mode runs three research subagents, a session-history probe, overlap checks, and specialized reviews. Lightweight mode writes the same document in one pass but skips subagents, overlap detection, session-history research, and semantic grounding validation. The project accepts lower coverage so lightweight runs fit the available context. [`docs/guides/ce-compound.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/ce-compound.md#L89-L99)
- **Autonomy prioritizes throughput over review points.** `lfg` does not pause for plan or diff approval, pushes when a remote exists, opens a PR, and repairs CI within a fixed limit on attempts. The docs recommend the staged skills when a person needs to inspect and approve each stage. Without a remote, the plugin creates local commits but does not open a PR or watch CI. [`docs/guides/lfg.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/lfg.md#L3-L9) [`docs/guides/lfg.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/lfg.md#L89-L93)
- **Independent review requires an available peer CLI.** An API key alone is insufficient. Without a peer CLI, the plugin performs the adversarial review in the current context and reports that the cross-model pass did not run. When users enable cross-model review, the plugin sends review content to another model-provider route. That creates a privacy and trust decision. [`docs/guides/ce-code-review.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/ce-code-review.md#L125-L135)
- **Cross-host support adds maintenance and compatibility constraints.** The repository warns that the documentation does not explain how several supported hosts can load an unreleased checkout. The contributor guide also requires skills to work across hosts with different capabilities. The converter and writer layer adds portability, but it also adds target-specific behavior and validation work. [`docs/development.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/development.md#L42-L46) [`CONTRIBUTING.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/CONTRIBUTING.md#L34-L38)
- **Compound Packs are experimental.** The project lists provider protocols, evidence locks and receipts, automatic updates, per-pack pinning within one source, cross-pack conflict detection, and transitive pack dependencies as features that the project has not built. Pack sources that the tool cannot fetch produce a warning, and planning continues without them. A missing remote pack can therefore remove expected guidance from a run. [`docs/guides/packs.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/packs.md#L1-L11) [`docs/guides/packs.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/packs.md#L243-L254) [`docs/guides/packs.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/docs/guides/packs.md#L310-L312)
- **It is opinionated.** The maintainers state that the project reflects a specific view of AI-assisted engineering and that they may reject proposals that do not fit it. Adoption therefore means accepting the workflow’s vocabulary, artifacts, and stage boundaries rather than treating it as a neutral agent toolkit. [`README.md`](https://github.com/EveryInc/compound-engineering-plugin/blob/4fbabcd32b6ca7d8ebb82f15840fe34ef7562a64/README.md#L448-L454)

**Bottom line.** Compound Engineering is a repository-based operating model built from specialized skills, durable artifacts, adaptive review, and constrained autonomous execution. Explicit work-source and shipping checks constrain autonomous execution. The workflow requires more process steps and context, host-specific integration, and, when users enable cross-model review or remote packs, dependence on external routes and their trust boundaries.
